## Product path

REPO-INSPECTION: `mix shoestring.plans request` reads a bounded goal-contract
JSON object and stores the immutable initial request, human attribution and
planner configuration. It performs no inference. `generate` explicitly admits,
charges and calls the configured tool-free planner through its existing bounded
Task supervisor. It shares the same allowance and replay behavior as amendment
and repair; it creates no plan revision, approval, task run or dispatch.

VERIFIED: the CLI tests exercise inert request/replay, missing-capacity blocking
before inference, admitted fixture generation, candidate visibility and repeated
result replay without another call. Invalid, oversized, malformed, non-object
and sensitive-field goal files produce no request and do not echo the input;
non-human request attribution is refused. Existing amendment/repair/review tests
continue through the same suite.

## Composed demo

VERIFIED: the isolated executor integration now follows this flow:

1. Prepare a tiny local Git repository with two initially failing fixture tests
   and a fixture goal. Goal insertion and synthetic capacity setup are test
   setup; this does not demonstrate a new goal-creation CLI.
2. Request and generate a deterministic planner candidate through the CLI.
   Review and adopt its exact digest as proposed revision 1.
3. Export the plan, edit `beta` to depend on `alpha`, and create proposed revision
   2. Execution before approval is refused as `:no_approved_authority`.
4. Approve the exact revision-2 digest and start bound execution through the CLI.
   The initial candidate revision remains intact.
5. Use the normal PlanExecutionWorker and DispatchWorker, supervised Fake and
   local `cat`, with deterministic code edits confined to allocated Git
   worktrees. A scripted quota refusal records a canonical checkpoint.
6. Restart the application, refresh synthetic capacity, and wake the same task
   attempt through WakeupWorker. The source checkout stays unchanged.
7. Accept the first task through its actual test gate, queue its dependent,
   restart again, and verify exact accepted execution state and one retained
   planning attempt. Finish the dependent and global gates without another
   planner call. Verify material code in the accepted worktree, two accepted
   tasks, three provider runs and two plan task attempts.
8. On a separate fixture goal, generate a cyclic candidate and inspect its
   visible `schema_failed` errors. It has no candidate, revision or task run.

VERIFIED: no lifecycle rows are edited to force this composed demo forward.
Synthetic provider capacity is ingested through Observatory; planning goes
through the CLI and execution/continuation through normal workers. Actual gate
commands and Git commits prove the code outcome. This extends the existing
quota/restart proof rather than replacing it with manually appended completions.
